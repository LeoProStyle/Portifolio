# Vendas (caixa + cupom não fiscal + estrutura NFC-e) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transformar `/vendas` num caixa que registra vendas na coleção `sales`, imprime comprovante não fiscal 80 mm e emite NFC-e por um provedor (Focus NFe) quando configurado.

**Architecture:** Regras puras em `lib/sales-rules.ts` (preço, pagamento, troco, permissões, prontidão fiscal) e serviço com Mongo em `lib/sales.ts`. O fiscal fica atrás da interface `FiscalProvider` (`lib/fiscal-provider/`), com implementações `focusnfe` e `mock`. Rotas finas em `app/api/vendas/**` no padrão `handler` + `requireSession/requireAdmin` + Zod. Telas client em `components/vendas/`.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, Mongoose 9, Zod 4, Tailwind v4, Vitest. Sem dependências novas.

**Spec:** [docs/superpowers/specs/2026-11-17-vendas-design.md](../specs/2026-11-17-vendas-design.md)

## Global Constraints

- Dinheiro em centavos inteiros; exibir com `formatBRL` (`lib/money.ts`).
- Dia = `todayKey()` de `lib/date.ts` (America/Sao_Paulo); nunca `toISOString().slice(0,10)`.
- Nada muda em Saída, Admin, Dashboard, Financeiro (exceção única: `print:hidden` no `AppHeader`, Task 8).
- Não alterar o model `Product`; dados fiscais do produto em `productfiscals`.
- Todo texto de UI e erro em pt-BR.
- Preço/nome sempre do banco no servidor; corpo da venda só traz `productId` + `qty`.
- Token do provedor só em env (`FISCAL_PROVIDER`, `FOCUS_NFE_TOKEN`, `FOCUS_NFE_ENV`); nunca devolvido pela API.
- Chamada ao provedor com tempo limite de **8 s**.
- Cancelamento fiscal: motivo ≥ **15** caracteres. Staff cancela só vendas de hoje; admin qualquer data.
- Formas de pagamento da venda: `01` Dinheiro, `17` PIX, `04` Débito, `03` Crédito, `11` Vale refeição, `10` Vale alimentação. Só `01` gera troco.
- Padrões fiscais: CFOP `5102`, CSOSN `102` (CRT 1/4), CST `00` (CRT 3), origem `0`, unidade `UN`.
- **Commits:** o usuário faz os próprios commits. No passo "Commit" de cada task, apenas liste os arquivos alterados.

## Review Focus

1. Clique duplo / rede lenta em "Finalizar" → uma única venda (mesmo `clientRef` devolve a mesma venda). Teste: e2e Task 5.
2. Produto desativado ou com preço alterado depois de o caixa carregar → servidor usa o preço atual e recusa inativo com o nome do produto. Teste: `priceItems` Task 2.
3. Provedor lento ou fora do ar → venda fica `erro`; "Tentar de novo" consulta pela `ref` antes de reenviar e nunca emite em dobro. Teste: mock Task 4 + e2e Task 5.
4. Pagamento dividido com dinheiro (ex.: R$ 20 dinheiro + R$ 15 débito, cliente entrega R$ 10) → recusa "Valor recebido em dinheiro menor que o valor em dinheiro". Teste: `settlePayments` Task 2.
5. Funcionário tentando cancelar venda de ontem ou abrir a configuração → 403. Teste: `canCancel` Task 2 + `isAdminPath` Task 1 + e2e Task 5.
