# RetroKey — Knowledge Base

> RetroKey is a browser-first retro gaming MVP: an NFC-style cartridge (`/nfc/[id]`) is validated against a game record and launches that game in an EmulatorJS iframe at `/play/[slug]`. It is a single Next.js 14 App Router app (TypeScript 5.6, React 18, Tailwind 3, Node 20.x) deployed on Vercel. Route handlers in `app/api/**` sit directly on `lib/` helpers that use the official MongoDB driver for games/cartridges and Cloudflare R2 (S3 client) for ROMs and `rooms.json`; every backend falls back to mock data, an in-memory admin store or local `public/roms`. The `/admin` area (games incl. ROM upload, cartridges) sits behind a NextAuth v5 credentials login that is checked only in the browser.

## Terminology
- **cartridge** — the `Cartridge` record linking an NFC tag to a game (not chaveiro/keychain record)
- **nfcId** — public token in `/nfc/[id]` URLs (not the cartridge `id`)
- **game** — the `Game` catalog entry (not rom/title)
- **slug** — normalized URL key: lowercase, non-alphanumerics → `-`
- **id** — app-level string `game-N` / `cartridge-N`, never Mongo `_id`
- **ROM** — the game binary, served only via `/api/rom/[slug]`
- **romPath** — R2 key when it starts with `roms/`, else a path under `public/`
- **system** — emulator platform that picks the core (`console` is a legacy alias)
- **core** — EmulatorJS core id (e.g. `fceumm`, `fbneo`), from `getCoreForSystem`
- **room** — a `Room` entry from R2 `rooms.json` or mock data
- **mock fallback** — `lib/mock-data.ts` data used when a backend is unavailable
- **admin store** — in-memory games/cartridges in `lib/admin-store.ts` when MongoDB is down
- **read model** — `lib/data.ts`, merging mock + MongoDB data for public reads
- **R2** — the Cloudflare R2 bucket (`R2_BUCKET_NAME`) for ROMs and `rooms.json`
- **admin** — the single NextAuth credentials user
